# Wallet ownership proof handoff contract

Status: design contract only. The Wallet App remains non-custodial and must not receive Task App authentication tokens.

## Scope

Support only NegosMint Task Platform wallet-ownership challenges on Ethereum Sepolia (chain ID 11155111). This is a message-signing operation, not a transaction. The Task App's server-generated challenge is the only message this dedicated flow may sign.

## Android transport

Use an explicit Android activity-result channel initiated by the Task App targeting the installed NegosMint Wallet package. Do not use a browsable custom-scheme callback for signatures and never put signatures in URI query parameters. The Android platform files are generated by the current CI workflow, so any native bridge implementation must be added to `tool/configure_android_ci.py` (or replace that generation strategy with tracked Android host files) and tested against the generated release project.

The wallet receives an untrusted envelope containing protocol version, challenge UUID, exact message, chain ID and expiry. Validate all fields and enforce strict size limits. Accept only the exact NegosMint ownership-verification purpose, the expected Task Platform identifier, Sepolia chain ID and an unexpired challenge. Do not accept arbitrary message-signing requests through this entry point.

## User approval and signing

- Show the exact message, requesting app, network, expiry and an explicit warning that no transaction will be sent.
- Require a deliberate approval action and local biometric/device authentication.
- Sign exact UTF-8 message bytes locally using the wallet's existing ownership-signing method.
- Confirm the derived signing address matches the wallet's public address.
- Return only the challenge UUID, public address, chain ID and signature through the originating activity result.
- Reject/cancel returns no signature. Invalid, expired, duplicate or unsupported envelopes must not invoke signing.
- Never transmit or log recovery phrases, private keys, PINs, biometric data or decrypted signing material. Never log the signature.

## Trust boundary

The wallet does not verify the Task App's user session and must not receive Supabase credentials. The Task App submits the result to its own authenticated server function, which binds the challenge to the authenticated user, verifies the exact signature and consumes the challenge atomically. The wallet result alone is not proof that the server accepted the link.

## Tests required

Cover malformed envelope, wrong purpose/app ID, wrong chain, expiry, user rejection, biometric failure, missing wallet, address mismatch, successful result shape, no signature in URL/logs, and app resume/relaunch behavior. Verify on a real Android device before release.
